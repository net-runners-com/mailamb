# mailamb 本番構築手順書

Bβ構成（既存メール鯖の転送 + Cloudflare + Thunderbird拡張、母艦PC不要）の本番構築手順。

## 前提

- 本手順書は、構築担当（エンジニア or AI assistant）が参照する。
- お客様の調査（`03_client側AIへの開始指示.md`）が完了し、本番構築の承認が得られていること。
- 以下の情報が揃っていること:
  - 既存メール鯖の種類と転送設定可否（例: Xserver, さくら, 独自）
  - 共有メールアドレス（例: info@yourcompany.com）
  - お客様の過去対応・定型文（匿名化済み、Markdown or プレーンテキスト）
  - お客様のCloudflare アカウント or 当社の運用アカウント
  - スタッフ名簿とそれぞれのスタッフID（重複しない識別子）

---

## 全体の流れ

```
[1] Cloudflare リソース作成
    ↓
[2] Worker デプロイ (mailamb + mailamb-email)
    ↓
[3] Email Routing セットアップ (CF側)
    ↓
[4] 既存メール鯖の転送設定 (お客様側)
    ↓
[5] ナレッジ投入 (過去対応・定型文)
    ↓
[6] 管理画面デプロイ
    ↓
[7] スタッフPCへの拡張配布
    ↓
[8] 動作確認 (E2E)
```

所要時間の目安: 構築 4〜6時間 / お客様側作業 1時間 / 拡張配布 10分 × スタッフ数。

## [1] Cloudflare リソース作成

### 1.1 Cloudflare アカウント準備

- 新規アカウントなら https://dash.cloudflare.com で作成
- 既存運用アカウントなら Worker リソース空き枠を確認

### 1.2 ドメイン追加（Email Routing 用）

Cloudflare dashboard → Add Site → `yourcompany-mailamb.workers.dev`（Workers 標準ドメイン）または独自ドメイン。独自ドメインの場合は MX / SPF 設定が必要。

### 1.3 CLI 認証

```bash
cd worker
npx wrangler login
# または当社ツール: cfauth init / cfauth login
```

### 1.4 KV / D1 / R2 / Vectorize 作成

```bash
# KV
npx wrangler kv:namespace create "PROCESSED"
# → 返される namespace_id を memo

# D1
npx wrangler d1 create mailamb
# → 返される database_id を memo

# R2
npx wrangler r2 bucket create mailamb-docs

# Vectorize
npx wrangler vectorize create mailamb-docs --dimensions=1024 --metric=cosine
```

### 1.5 `worker/wrangler.toml` を本番用に編集

```toml
name = "mailamb"
main = "src/index.ts"
compatibility_date = "2026-10-01"
compatibility_flags = ["nodejs_compat"]

[[kv_namespaces]]
binding = "PROCESSED"
id = "<1.4で取得したKV ID>"

[[d1_databases]]
binding = "DB"
database_name = "mailamb"
database_id = "<1.4で取得したD1 ID>"

[[r2_buckets]]
binding = "DOCS"
bucket_name = "mailamb-docs"

[[vectorize]]
binding = "VECTORIZE"
index_name = "mailamb-docs"

[ai]
binding = "AI"

[vars]
GEN_MODEL = "@cf/meta/llama-3.3-70b-instruct-fp8-fast"
EMBED_MODEL = "@cf/baai/bge-m3"
RAG_THRESHOLD = "0.5"
RAG_TOP_K = "5"
TEMPERATURE = "0.1"
```

### 1.6 D1 スキーマ初期化

```bash
cd worker
npx wrangler d1 execute mailamb --file=./migrations/0001_init.sql
```

## [2] Worker デプロイ

### 2.1 API Key 生成とシークレット登録

```bash
# 64文字のランダム Key を生成
API_KEY=$(openssl rand -hex 32)
echo "API_KEY: $API_KEY"   # 後で各PC・管理画面にも入れる値

# mailamb Worker にシークレット登録
cd worker
echo -n "$API_KEY" | npx wrangler secret put API_KEY

# mailamb-email Worker にも同じ値を登録
cd ../worker-email
echo -n "$API_KEY" | npx wrangler secret put MAILAMB_API_KEY
```

**API Key は 1Password 等に即保管**。これを失うと管理画面やTB拡張が全部動かなくなる。

### 2.2 デプロイ

```bash
cd worker
npx wrangler deploy
# → "Deployed mailamb" + URL が出る
#   例: https://mailamb.<account-subdomain>.workers.dev

cd ../worker-email
npx wrangler deploy
```

### 2.3 デプロイ確認

```bash
curl https://mailamb.<subdomain>.workers.dev/health
# → {"ok":true,"service":"mailamb","model":"@cf/meta/llama-3.3-70b-instruct-fp8-fast"}
```

## [3] Email Routing セットアップ

### 3.1 Cloudflare dashboard

対象ゾーン → **Email** → **Email Routing** → **Routes** タブ

### 3.2 Custom addresses 追加

- **Address**: `receive@yourcompany-mailamb.workers.dev`
- **Action**: **Send to a Worker**
- **Destination**: `mailamb-email` を選択
- Save

### 3.3 Catch-all 設定（任意）

誤転送をキャッチする場合は catch-all を `mailamb-email` または破棄に設定。

### 3.4 動作確認

ダッシュボードの受信ログで、転送が成功して Worker invocation が記録されているか確認（お客様側転送設定後にテスト）。

## [4] 既存メール鯖の転送設定（お客様側）

### 4.1 Xserver の場合

1. サーバーパネル → **メールアカウント設定**
2. 対象アカウント（`info@yourcompany.com`）の **「転送」** タブ
3. **転送先アドレス** に `receive@yourcompany-mailamb.workers.dev`
4. **「メールボックスにも残す」** に☑（必須）
5. 設定を追加 → 反映

### 4.2 さくらの場合

さくらサーバーコントロールパネル → **メール** → **メールアドレスの管理** → 対象アカウント → **転送先設定**

### 4.3 Google Workspace の場合

**管理コンソール** → **アプリ** → **Google Workspace** → **Gmail** → **ルーティング** → 新規ルール追加

### 4.4 M365 の場合

Exchange 管理センター → **メールフロー** → **ルール** → 新規ルール

### 4.5 動作確認

自分の個人メールから `info@yourcompany.com` にテスト送信 → 1分以内に:
- お客様 Inbox にそのまま届く
- CF Email Routing の log にも転送が記録される

## [5] ナレッジ投入

### 5.1 お客様から受領した定型文・過去対応を Markdown 化

匿名化済みの以下を揃える:
- 新規見積依頼返信テンプレ
- 過去対応事例（お客様の種類別、サイト種別）
- お断りテンプレ
- 保守運用・サポート案内
- フォールバック（該当なし時の返信）

目安: **初期20〜30件**、業務カバー度を見ながら増やす。

### 5.2 一括投入

**方法A: 管理画面から1件ずつ**（[7]でデプロイ後）

**方法B: ingest スクリプト**

```bash
cd poc
# docs/ 配下の .md ファイルを一括 ingest
pnpm run upload-to-worker
```

### 5.3 投入確認

```bash
curl -s "https://mailamb.<subdomain>.workers.dev/api/documents" \
  -H "X-API-Key: $API_KEY" | jq '.[] | {doc_id, title}'
```

## [6] 管理画面デプロイ

### 6.1 Cloudflare Pages にデプロイ

```bash
cd admin
npx wrangler pages deploy . --project-name mailamb-admin
# → https://mailamb-admin.pages.dev がURL
```

### 6.2 アクセス制限

**Cloudflare Access** を Pages プロジェクトに適用:

1. Zero Trust → Access → Applications → Add
2. Self-hosted アプリ、ドメイン: `mailamb-admin.pages.dev`
3. Policy: Google Workspace の社員メール or Email allowlist
4. Save

### 6.3 初回設定

管理者 PC から `https://mailamb-admin.pages.dev` → 設定タブ → Worker URL + API Key 入力（ローカルストレージ保存）→ 問い合わせ活動タブに切り替わる

## [7] スタッフPCへの拡張配布

### 7.1 配布パッケージ準備

当社から受け取った `mailamb-staff-package-X.Y.Z.zip` の `設定メモ.txt` に以下を記入:

- Worker URL（[2.2] のURL）
- API Key（[2.1] の値）
- 問い合わせ宛先（`info@yourcompany.com` 等）

### 7.2 スタッフに配布

Slack / 社内チャット / USB等で `.zip` を各PCへ配布。スタッフID はスタッフごとに決めて記入。

### 7.3 各スタッフが `INSTALL.md` に沿って作業

所要時間: 10分 × スタッフ数。拡張の読み込みに TB再起動必須。

### 7.4 動作確認（スタッフごと）

`SELF_CHECK.md` の6ステップを実施。特に:
- 自動 Drafts 保存
- バナー表示
- 送信済み状態の共有（他スタッフと一緒にテスト）

## [8] E2E 動作確認

### 8.1 本番疎通テスト

1. 外部メールから `info@yourcompany.com` に問い合わせっぽいメールを送る
2. 1分以内に:
   - 全スタッフの受信トレイに届く
   - 下書きフォルダに `Re: ...` が自動で現れる（AI下書き本文入り）
3. いずれかのスタッフが下書きを開く → 本文バナー `🤖 AI下書き準備済`
4. そのスタッフが送信ボタン → Sent フォルダに移動
5. **別のスタッフが同じ元メールを開く** → バナー `✉️ 送信済: XX`
6. **別スタッフが同じメールに返信しようとする** → 送信時にポップアップ `⚠️ 既に送信済`

### 8.2 ナレッジヒット確認

管理画面 → 問い合わせ活動 → 詳細 → RAG ヒット列に有効な定型文が0.6以上でヒットしてるか。ヒット率が低ければナレッジ追加。

### 8.3 コスト確認

Cloudflare dashboard → Workers → 使用量 → Workers AI / Vectorize のリクエスト数を確認。10名規模の想定負荷:

| サービス | 月想定 | 無料枠 |
|---|---|---|
| Workers (requests) | 10,000〜30,000 | 100,000/day |
| Workers AI (generation + embedding) | 2,000〜5,000 | 10,000/day |
| Vectorize (queries) | 2,000〜5,000 | 30,000/month |
| KV (reads/writes) | 10,000 | 100,000/day read |
| D1 / R2 | 微少 | 大枠内 |

実質 **月額 $0〜数ドル**。

## [9] 運用引き継ぎ

### 9.1 お客様管理者に渡すもの

- 管理画面 URL（`https://mailamb-admin.pages.dev`）
- 管理画面ログイン方法（Cloudflare Access 経由）
- ナレッジ追加・更新の操作ガイド（管理画面の README）
- トラブル時の連絡先

### 9.2 定期メンテ運用

| 頻度 | 作業 |
|---|---|
| 月1 | ナレッジ棚卸し（よく使われた / 使われなかった） |
| 月1 | 問い合わせ活動一覧をざっと見てAI下書き品質確認 |
| 四半期 | コスト確認 |
| 都度 | 新スタッフID追加、拡張再配布 |
| 都度 | 退職者ID無効化（KV の state クリーンアップ） |

### 9.3 障害時フォールバック

Cloudflare 側障害時 → 下書きが出ないだけ。既存メール運用（Inbox 受信・返信）は無事。手動返信すればOK。復旧後は自動で再開。

## [10] アンインストール手順（必要時）

### 10.1 お客様鯖側

転送設定を削除（Xserver 管理画面）。これで CF への流入が止まる。

### 10.2 Cloudflare 側

```bash
cd worker-email && npx wrangler delete mailamb-email
cd worker && npx wrangler delete mailamb
npx wrangler kv:namespace delete <id>
npx wrangler d1 delete mailamb
npx wrangler r2 bucket delete mailamb-docs
npx wrangler vectorize delete mailamb-docs
```

### 10.3 各スタッフPC

拡張をアンインストール（`INSTALL.md` 末尾参照）。

### 10.4 ナレッジ資産の持ち出し

```bash
# D1 からナレッジ一覧エクスポート
curl -s "https://mailamb.<subdomain>.workers.dev/api/documents" \
  -H "X-API-Key: $API_KEY" > knowledge-backup.json
# R2 から本文エクスポート（ナレッジ本体）
npx wrangler r2 object get mailamb-docs/<doc_id>.md --file ./backup/<doc_id>.md
```

これらを `.md` ファイルで持ち出せば、他環境でも再利用可能。
