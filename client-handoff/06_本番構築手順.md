# mailamb 本番構築手順書

**minimal構成** (worker-watcher + mailamb Worker + TB拡張) の本番構築手順。

## この構成でできること

- ✓ 既存メール鯖 (Xserver等) に **DNS変更なし**
- ✓ **ドメイン追加なし**
- ✓ **母艦PC不要**
- ✓ **完全無料** (Cloudflare Free Plan)
- ✓ 新着検知 **最大5秒遅延** (実質リアルタイム)
- ✓ **二重送信防止** (スタッフ間で送信状態を共有)

## 前提

- お客様が独自ドメインを Xserver 等で契約・運用中 (例: `info@yourcompany.com`)
- 約5名のスタッフが Thunderbird で共有IMAP同期して運用
- Cloudflare アカウント (無料でOK)
- お客様の過去対応・定型文 (Markdown or プレーンテキスト)

## 全体の流れ

```
[1] Cloudflare アカウント準備
    ↓
[2] mailamb Worker 構築 (AI生成 API)
    ↓
[3] ナレッジ投入 (過去対応・定型文)
    ↓
[4] worker-watcher 構築 (IMAP監視, 下書き保存)
    ↓
[5] 動作確認
    ↓
[6] スタッフPCへの拡張配布
```

所要時間: **2〜3時間** (ナレッジ量次第)

## [2] mailamb Worker 構築

### 2.1 CF リソース作成

```bash
cd worker

npx wrangler kv:namespace create "PROCESSED"
# → 返される id を memo

npx wrangler d1 create mailamb
# → 返される database_id を memo

npx wrangler r2 bucket create mailamb-docs

npx wrangler vectorize create mailamb-docs --dimensions=1024 --metric=cosine
```

### 2.2 wrangler.toml 編集

`worker/wrangler.toml` の以下を取得した値に書き換え:

```toml
[[kv_namespaces]]
binding = "PROCESSED"
id = "<2.1のKV id>"

[[d1_databases]]
binding = "DB"
database_name = "mailamb"
database_id = "<2.1のD1 id>"
```

### 2.3 D1 スキーマ初期化
```bash
npx wrangler d1 execute mailamb --file=./migrations/0001_init.sql
```

### 2.4 API Key 生成 + Secret 登録

```bash
API_KEY=$(openssl rand -hex 32)
echo "API_KEY: $API_KEY"   # 1Password 等に保管

echo -n "$API_KEY" | npx wrangler secret put API_KEY
```

### 2.5 デプロイ
```bash
npx wrangler deploy
# → URL: https://mailamb.<account>.workers.dev
```

### 2.6 健全性確認
```bash
curl https://mailamb.<account>.workers.dev/health
# → {"ok":true,"service":"mailamb",...}
```

## [3] ナレッジ投入

### 3.1 お客様固有のナレッジ準備

- 過去対応事例 5〜15件 (inquiry/reply ペア)

## [4] worker-watcher 構築 (IMAP監視・AI下書き・Drafts保存)

### 4.1 Xserver から IMAP情報 取得

Xserver サーバーパネル → メールアカウント設定 → 対象アカウント → 設定情報:
- IMAP サーバ名 (例: `sv1234.xserver.jp`)
- IMAP ポート (993, SSL)
- アカウント名 (例: `info@yourcompany.com`)
- パスワード
- Drafts フォルダパス (多くは `INBOX.Drafts`、要実機確認)

### 4.2 Secret 登録

```bash
cd ../worker-watcher

npx wrangler secret put IMAP_HOST       # sv1234.xserver.jp
npx wrangler secret put IMAP_PORT       # 993
npx wrangler secret put IMAP_USER       # info@yourcompany.com
npx wrangler secret put IMAP_PASSWORD   # 平文
npx wrangler secret put IMAP_DRAFTS     # INBOX.Drafts
npx wrangler secret put MAILAMB_API_KEY # 2.4 の API_KEY と同じ
```

### 4.3 デプロイ
```bash
npx wrangler deploy
# → URL: https://mailamb-watcher.<account>.workers.dev
# → cron 毎分発火開始
```

### 4.4 動作確認
```bash
# tail でログ監視
cfauth exec -- npx wrangler tail --format pretty &
# → [imap] greet / LOGIN / SELECT INBOX / IDLE 開始 等が流れる
```

## [5] 動作確認 (E2E)

### 5.1 本番疎通テスト

1. 別アドレスから `info@yourcompany.com` に問い合わせっぽいメール送信
2. 1〜2分以内に:
   - スタッフ TB の Inbox に届く（既存通り）
   - **Drafts フォルダに `Re: ...` 自動出現** (worker-watcher が APPEND)
3. 下書きの本文に AI生成の返信文（挨拶 + ヒアリング要項 + 末尾）が入っている

### 5.2 ナレッジヒット確認

管理者用TB拡張 [addon-admin/](../addon-admin/) → ナレッジタブ、または Worker ログ `wrangler tail` でRAGヒットスコア確認。
スコア 0.6 以上の有効ヒットが出てれば OK。低ければナレッジ追加。

## [6] スタッフPCへの拡張配布

### 6.1 配布パッケージ準備

[mailamb-staff-package-0.18.0.zip](../mailamb-staff-package-0.18.0.zip) を解凍。
`設定メモ.txt` に:

```
Worker URL:  https://mailamb.<account>.workers.dev   ← [2.5]のURL
API Key:     <64文字>                                 ← [2.4]のAPI_KEY
```

を管理者が記入。

### 6.2 配布

Slack / 社内チャット / USB 等で各スタッフに zip 配布。

### 6.3 各スタッフが INSTALL.md に沿って作業

所要時間: 各PC 10分。

- user.js に未署名許可追加
- xpi を profile の extensions/ に配置 (ファイル名 `mailamb@mailamb.local.xpi` に rename)
- TB 完全再起動
- 拡張オプションで 3項目入力 (Worker URL / API Key / **スタッフID**)
  - スタッフID はスタッフ本人が決める (`tanaka`, `SK` 等、他スタッフと重複しない識別子)

### 6.4 動作確認 (スタッフごと)

[SELF_CHECK.md](../addon/SELF_CHECK.md) 参照。特に:
- 送信前の二重返信確認ポップアップ
- 本文バナー (送信済 / 返信中)

## 運用引き継ぎ

### お客様管理者に渡すもの
- Worker URL (管理画面接続用)
- API Key (1Password 等で安全に共有)
- ナレッジ追加・更新のガイド
- トラブル時の連絡先

### 定期メンテ
| 頻度 | 作業 |
|---|---|
| 月1 | ナレッジ棚卸し (使用頻度 / 使われない定型文) |
| 月1 | AI下書き品質スポットチェック |
| 四半期 | コスト確認 (通常は$0) |
| 都度 | 新スタッフID追加、拡張配布 |

### 障害時フォールバック

- CF側障害 → 新規下書きが止まるだけ、既存メール送受信は無事
- Xserver 側障害 → mailamb の問題ではない
- IMAP パスワード変更時 → `wrangler secret put IMAP_PASSWORD` で更新

## アンインストール

### Cloudflare 側
```bash
cd worker-watcher && npx wrangler delete mailamb-watcher
cd ../worker && npx wrangler delete mailamb
npx wrangler kv:namespace delete <id>
npx wrangler d1 delete mailamb
npx wrangler r2 bucket delete mailamb-docs
npx wrangler vectorize delete mailamb-docs
```

### 各スタッフPC
拡張をアンインストール ([addon/INSTALL.md](../addon/INSTALL.md) 末尾参照)。

### Xserver 側
**何もしなくていい**。元の設定に戻す作業ゼロ。

## 代替構成 (必要時のみ)

このminimal構成が合わない場合の選択肢:
- **母艦PC方式** ([poc/scripts/05-mother.ts](../poc/scripts/05-mother.ts)): 常駐PCがあり CF 使いたくない場合
- **Email Routing方式**: ドメインを CF に追加できる場合は worker-email を自前実装

いずれも関連ソースはリポに同梱、本番で使う前提ではない (minimal構成で十分なため)。
