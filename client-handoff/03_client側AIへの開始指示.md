# お客様側AIへの開始指示

次の文章を、母艦PCのAIへそのまま渡します。

```text
添付した `01_提案構成と導入方針.md` と `02_テスト開始前の確認事項.md`、およびコンサルから共有された `mailamb-flow.txt` を読んでください。

mailambのテスト環境構築を検討します。前提は次の通りです。
- 問い合わせ用メールは共有アカウント1個のみ（Xserver等のレンタルサーバ）
- 約5名のスタッフが各PCの Thunderbird からIMAP同期して共有閲覧
- Gmail / Workspace は使っていない。追加発行もしない
- 既存の共有メールサーバはそのまま利用する
- 母艦PCは不要。鯖側に転送設定を1行追加し、Cloudflareがリアルタイムで受け取る方式
- 下書きは Thunderbird拡張 が新着検知時にDraftsへ自動保存する

まず、お客様事務所の問い合わせ用共有メールアカウントと、約5名のスタッフが各PCのThunderbirdで行っている受信、返信、下書き共有の運用を読み取りだけで確認してください。スタッフ個人の私用メールは対象にしません。Cloudflare、Thunderbird拡張は、現在の事務所環境にある前提にせず、テスト環境で新たに用意する候補として扱ってください。

特に次の技術情報を把握してください（接続テストは行わず、設定値の確認のみ）。
- 共有IMAPのホスト名、ポート、暗号化方式（SSL/STARTTLS）
- 共有SMTPのホスト名、ポート、認証方式
- 現在のDraftsフォルダのパス（Drafts / INBOX.Drafts / 下書き 等）
- 鯖側に IMAP APPEND の制限や、Draftsへの書き込みを拒否する設定がないか
- 鯖側の「転送設定」機能の有無と、外部ドメイン宛てへの転送可否（原本は残す形で、コピーを外部へ送れるか）。例: Xserver なら「メールアカウント設定 → 転送」
- 現在のスタッフが共有Draftsをどう使っているか（下書きの命名、担当者の表明方法、送信済み共有の方法）
- 既読フラグ運用（誰かが開いたら全員既読になる現象への対処有無）
- 定型文・過去メール・ナレッジの保管場所と形式

確認した事実、未確認事項、提案構成との差分、テスト環境に必要な認証や費用の有無を分けて提示してください。既存の `mailamb` プロジェクトが確認できた場合だけ、その中の `docs/00_現状調査.md` に記録してください。プロジェクトが無い場合は、新規作成を行わず、作成予定の実在パスと構成案を示してください。メール本文、氏名、メールアドレス、認証情報、トークン、パスワードを資料へ記録してはいけません。

現状調査の後、次を一度に提示してください。

1. テスト環境で使える既存要素（共有IMAP接続情報の形）
2. 新規作成が必要なCloudflareリソース
3. テスト用に必要な共有IMAPアカウント、Thunderbirdプロファイル、拡張機能の構成
4. テスト用の鯖側転送設定の設定場所と記入内容イメージ
5. 本番環境とテスト環境を混ぜない方法（別IMAPアドレス、別転送先、別TBプロファイル、別KV等）
6. 費用、認証、メール設定変更の有無（本番MX/SPF/DKIMには一切触らない）
7. テスト開始前にお客様の確認が必要な事項

この時点では、Cloudflareへのデプロイ、Cloudflareリソース作成、本番メール設定変更、実メールの取得と送信、Thunderbird拡張の本番PC導入、課金設定を行わないでください。

お客様が調査結果を確認し、開始を承認した後だけ、テスト専用のCloudflareリソース、テストデータ、テスト用共有IMAPアカウント、テスト用Thunderbird環境を使って、段階的に実装してください。
```
