# お問い合わせメールの返信下書き支援について

## ご相談したいこと

お問い合わせメールへの返信を、過去の対応方針や定型文を活かしながら、より早く安定して作れるようにしたいと考えています。

AIが返信の下書きを用意し、スタッフの方が内容を確認、必要なら編集してから送信する仕組みです。AIが自動でメールを送ることはありません。

## 今回お渡しする資料

1. `01_提案構成と導入方針.md`
   - 予定している仕組みと、各部品の役割
2. `02_テスト開始前の確認事項.md`
   - お客様事務所の問い合わせ用共有メール運用と照合する事項
3. `03_client側AIへの開始指示.md`
   - 母艦PCのAIへ渡す調査フェーズの指示
4. `04_お客様へお送りするメッセージ.txt` / `05_コンサルへ確認をお願いするメッセージ.txt`
   - 連絡文テンプレ
5. `06_本番構築手順.md`
   - 承認後の本番構築手順（Cloudflare / 鯖転送 / ナレッジ / 拡張配布 まで）
6. `07_サブドメイン委譲手順.md`
   - 既存独自ドメインに無影響でCF Email Routingを導入する手順（Xserver想定）

コンサルから共有された `mailamb-flow.txt` は、この資料一式の構成根拠です。

## 今回お願いしたいこと

最初にお願いしたいのは、お客様事務所で使っている問い合わせ用共有メールアカウント（Xserver 等のレンタルサーバ想定）と、各スタッフPCのThunderbirdでの受信、返信、共有の運用を読み取りで確認することだけです。スタッフ個人の私用メールは対象にしません。Cloudflare は現在の事務所環境には無く、テスト環境で新たに用意する候補です。既存の共有メールサーバはそのまま利用し、Gmail等への切り替えや追加アカウント発行は想定しません。

この段階では、メール送信、メール設定の変更、本番メールの転送、実際のお客様メールの利用、費用が発生する設定、本番PCへの拡張機能導入は行いません。

現状調査の結果を確認した後、テスト専用環境を作るかを判断します。

## 先に確認したい二つのこと

1. 問い合わせ用共有メールアカウントとThunderbirdの現在の運用を読み取りで確認してよいか
2. 調査結果を見た後、テスト専用環境を作るか判断してよいか
