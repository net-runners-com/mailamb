# mailamb サブドメイン委譲 構築手順

**既存の独自ドメイン (Xserver 契約) に一切影響を与えず**、CF Email Routing で mailamb を動かす構成の構築手順。

## 対象ケース

- Xserver で独自ドメイン（例: `yourcompany.com`）を契約済み
- そこで `info@yourcompany.com` 等の共有メールを運用中
- MX / Web / 既存メール設定を **一切変えずに** mailamb を導入したい
- 母艦PCは置きたくない / 新規ドメインも取りたくない

## 構成概要

```
yourcompany.com (Xserver DNS管理のまま)
├─ MX = Xserver (既存通り)
├─ info@yourcompany.com → Xserver IMAP (既存通り、全スタッフが見る)
├─ Web / A record / その他 (既存通り)
│
└─ サブドメイン mail-ai.yourcompany.com (CFに委譲)
   ├─ NS = Cloudflare (Xserver DNSに 4行追加するだけ)
   ├─ MX = Cloudflare (Email Routing 自動設定)
   └─ receive@mail-ai.yourcompany.com → mailamb-email Worker

[運用時]
顧客 → info@yourcompany.com (Xserver受信)
        ├─► 既存Inbox (スタッフTB)                     ← 顧客視点はここで完結
        └─► 転送設定でコピー → receive@mail-ai.yourcompany.com
             → CF Email Routing
             → mailamb-email Worker
             → AI下書き生成 → KV保存
             → スタッフTB拡張が検知 → Drafts自動保存
```

**ポイント**:
- `yourcompany.com` の DNS はほぼ無変更（NS record 1組追加のみ）
- MX は Xserver のまま
- 顧客に見せるアドレスも `info@yourcompany.com` のまま
- `mail-ai.yourcompany.com` は社内専用、顧客に見せない

---

## STEP 1: Cloudflare 側でサブドメインを Zone 追加

### 1.1 Cloudflare dashboard

- https://dash.cloudflare.com にログイン（お客様アカウント or 当社運用アカウント）
- **Add site** → ドメイン名欄に **`mail-ai.yourcompany.com`** （サブドメイン）を入力
- Free plan で OK → Continue

### 1.2 CF から渡される NS record をメモ

CF が「このドメインを管理するには、以下のネームサーバーに切り替えてください」と4つの NS を表示する:

```
例:
  ns1.cloudflare.com
  ns2.cloudflare.com
  (またはランダムな ns ホスト名、2〜4個)
```

→ この値を STEP 2 で Xserver に設定する。

---

## STEP 2: Xserver 側で NS record を追加

### 2.1 Xserver サーバーパネルにログイン

- サーバーパネル → **DNS設定** → 対象ドメイン（`yourcompany.com`）選択 → **DNSレコード設定**

### 2.2 サブドメインの NS record を追加

対象ドメイン `yourcompany.com` の DNS に、以下を**4行追加**（STEP 1.2 の CF が指定した NS 分）:

| ホスト名 | 種別 | 内容 |
|---|---|---|
| `mail-ai` | NS | `ns1.cloudflare.com` (CF指定) |
| `mail-ai` | NS | `ns2.cloudflare.com` (CF指定) |
| (追加分あればそれも) | NS | |

**既存の DNS record には一切触らない** (MX, A, TXT, SPF, DKIM 等そのまま)。

### 2.3 伝播待ち

NS 変更は 5分〜数時間で伝播。CF dashboard の **「Overview」** に戻って `mail-ai.yourcompany.com` の status が **Active** になるまで待つ。

```bash
# 伝播確認コマンド
dig NS mail-ai.yourcompany.com
# → cloudflare.com の NS が返ってくれば OK
```

---

## STEP 3: Cloudflare Email Routing 有効化

### 3.1 対象ゾーン選択

CF dashboard → `mail-ai.yourcompany.com` ゾーン → **Email** → **Email Routing**

### 3.2 Enable Email Routing

- **Enable Email Routing** ボタンをクリック
- CF が自動的に以下の DNS record を追加:
  - MX record (CF受信用)
  - TXT record (SPF)
- これらは `mail-ai.yourcompany.com` のサブドメインに適用、親ドメインには影響なし

### 3.3 Destination addresses 設定

- **Destination addresses** タブ → **Add destination address**
- 自分で受信確認できるアドレス（例: 管理者のメール）を入力
- CF から認証メールが届くので確認リンク押下

## STEP 5: Email Routing Routes 設定

CF dashboard → `mail-ai.yourcompany.com` → Email Routing → **Routes** タブ

### 5.1 Custom addresses 追加

- **Create address** クリック
- **Custom address**: `receive@mail-ai.yourcompany.com`
- **Action**: `Send to a Worker`
- **Worker**: `mailamb-email` を選択
- Save

### 5.2 動作確認

```bash
# 任意の個人メールから送信してテスト
# From: your-gmail@gmail.com
# To: receive@mail-ai.yourcompany.com
# Subject: 疎通テスト
```

CF Email Routing dashboard の **Activity log** で受信 → Worker起動が記録されていればOK。

---

## STEP 6: Xserver 転送設定（本番接続）

### 6.1 Xserver サーバーパネル

- **メールアカウント設定** → 対象アカウント（`info@yourcompany.com`）
- **転送** タブ

### 6.2 転送先追加

| 項目 | 値 |
|---|---|
| 転送先アドレス | `receive@mail-ai.yourcompany.com` |
| メールボックスにも残す | **☑ 必須**（スタッフ Inbox で見るため） |

### 6.3 動作確認

```bash
# 外部アドレスから info@yourcompany.com にメール送信
```

- 1分以内に:
  - スタッフ TB の Inbox に届く（Xserver 既存通り）
  - CF Email Routing dashboard にも受信ログ
  - mailamb Worker の log に処理ログ
  - KV に下書き保存

## 影響範囲サマリー

| 対象 | 変更 |
|---|---|
| yourcompany.com MX | ✗ 変更なし (Xserverのまま) |
| yourcompany.com SPF / DKIM | ✗ 変更なし |
| yourcompany.com A / その他レコード | ✗ 変更なし |
| yourcompany.com Web ホスティング | ✗ 変更なし |
| info@yourcompany.com 受信 | ✗ 変更なし (Xserverのまま) |
| info@yourcompany.com 送信 (SMTP) | ✗ 変更なし |
| スタッフTBのIMAP設定 | ✗ 変更なし |
| **DNS 追加** | ✓ NS record 2〜4行 (`mail-ai` サブドメインの委譲) |
| **メール転送追加** | ✓ info@〜 の転送に 1行 (`receive@mail-ai.〜`) |
| **CF 側** | ✓ サブドメイン Zone 追加、Email Routing 設定、Workerデプロイ |

**既存運用が壊れるリスク = ゼロ** (DNS追加・転送追加は非破壊操作)。

## ロールバック

mailamb を止めたくなった場合:

1. **Xserver 転送設定を削除** → CF への流入が止まる
2. 既存メール運用は完全無傷で継続
3. 必要なら CF 側リソース削除 (`wrangler delete`)
4. 必要なら Xserver DNS の `mail-ai` NS record を削除

既存ドメイン運用に戻すのは**どのステップでも元に戻れる**。

## トラブルシュート

### サブドメインが Active にならない

- `dig NS mail-ai.yourcompany.com` で確認
- Xserver DNS に NS record が正しく追加されているか確認
- TTL が長い場合、数時間待つ

### Email Routing が受信できない

- CF dashboard → Email Routing → Routes タブで destination address が verified になってるか
- MX record が自動で追加されたか確認: `dig MX mail-ai.yourcompany.com`

### Xserver 転送が外部ドメインを拒否する

- 一部の Xserver プランで「同一ドメイン宛てしか転送不可」設定の可能性
- サーバーパネル → メール設定 → 迷惑メール/転送制限 を確認
- どうしても無理なら「母艦方式」( [docs/08-mail-environments.md](../docs/08-mail-environments.md) 参照) にフォールバック

### CF 受信時に SPF 失敗

- Xserver からの転送時に `Return-Path` が変わらないため CF 側で SPF 失敗する場合あり
- CF Email Routing は Received-SPF 失敗でも受信は通す設定が可能
- 必要なら Xserver 側に SPF の include 追加検討

## よく使うコマンド

```bash
# サブドメインの NS 確認
dig NS mail-ai.yourcompany.com +short

# MX 確認 (CF 自動設定後)
dig MX mail-ai.yourcompany.com +short

# 既存 yourcompany.com の MX が無傷か確認
dig MX yourcompany.com +short
# → Xserver のMX がそのまま返ってくるはず

# Worker の log 監視
cd worker-email && npx wrangler tail --format pretty
```
