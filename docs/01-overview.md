# 01. 概要

## 課題

当社では問い合わせメールへの返信を全スタッフ 10 名で手分けして処理している。

- 問い合わせは種類が多い（新規見積、改修、保守、資料請求、契約、採用、緊急不具合 等）
- よくある質問は定型化できるが、都度書くのは時間の無駄
- スタッフにAIを直接使わせる = サボりやクオリティばらつきが心配
- 既存の定型文集は Google Drive 等に散らばっており、使われないまま古くなる

## 解決方針

**AI は裏方、人間は最終判断** という設計。

1. 問い合わせメールが届くと、Cloudflare Workers AI が自動で返信下書きを作る（RAG で過去対応と定型文から参照）
2. 下書きはスタッフの Thunderbird に表示される（拡張機能経由）
3. スタッフは下書きを **確認・編集** して送信ボタンを押す
4. AI の生成コストと知的作業（定型文メンテ・プロンプト）は管理者側に集約

スタッフは普段通り Thunderbird を使うだけで、生成 AI の操作は一切しない。

## 業務フロー

```mermaid
flowchart LR
    A[顧客] -->|問い合わせメール| B[info@example.com]
    B --> C[Cloudflare Email Worker]
    C --> D[Workers AI<br/>RAG + 下書き生成]
    D --> E[KV に下書き保存]
    C --> F[各スタッフGmailへ転送]
    F --> G[スタッフのThunderbird]
    G --> H{🤖 mailamb拡張<br/>下書き表示}
    H -->|確認・編集| I[スタッフ送信]
    I --> A
```

## 期待効果

| 項目 | 従来 | mailamb |
|---|---|---|
| 返信までの時間 | 30分〜数時間 | 下書きまで15秒、人間編集5分 |
| 返信品質のばらつき | 大 | 定型ベースで安定 |
| 定型文の鮮度 | 誰も更新しない | 使用ログで古いテンプレ検出 |
| AI操作スキル | スタッフ必要 | 不要（画面に表示されるだけ） |
| サボり防止 | — | AI生成UIは管理者のみ |

## 対象メールと除外対象

**処理対象**:
- info@example.com 宛の外部からの問い合わせ

**自動スキップ**（前処理フィルタ）:
- 件名に「【営業】」等を含むもの
- 「突然のご連絡失礼いたします」で始まる営業パターン
- NG顧客リスト（D1に登録、送信前に排除）
- 採用応募

**処理対象外**（Email Routing レベルで除外）:
- 社内メール（同ドメイン送信元）
- 自動返信（Auto-Submitted ヘッダ）
- メルマガ（List-Unsubscribe ヘッダ、将来実装）

## スケール想定

| 規模 | 対応状況 |
|---|---|
| 1日の問い合わせ件数 | ~50通まで余裕（CF Workers 無料枠内） |
| スタッフ数 | 10名（CF Email Routing の destinations で管理） |
| テンプレ数 | 現在9種 + 過去対応10件、将来100件程度まで Vectorize で高速検索 |
| 1件あたりコスト | 無料枠内（Workers AI は $0 / 従量課金に移行時 $0.0001 程度/件） |

## 本番運用の想定フェーズ

- **Phase 1（現在）**: 1アカウント(forward@example.com) + info@転送 でPoC検証
- **Phase 2**: スタッフ各自のメアドを verified destinations に追加 → 複数転送
- **Phase 3**: Gmail Send As 設定で info@/担当者@ 名義での送信を実現
- **Phase 4**: 使用ログからテンプレ鮮度・編集率を可視化、改善サイクル確立
